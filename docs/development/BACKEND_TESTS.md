# Backend API tests

Run `pnpm test:backend` for `tests/backend/**/*.test.mjs`, or `pnpm test` for the complete existing Vitest suite. Stubbed Fastify injection tests run without PostgreSQL. Database-backed tests in this folder use `test.skipIf(!process.env.TEST_DATABASE_URL)` and `createBackendTest()` from `tests/backend/helpers.mjs`.

For database-backed tests, create a **dedicated**, disposable PostgreSQL database whose name ends in `_test` (for example, `createdb storyteller_test`). Set `TEST_DATABASE_URL=postgresql://localhost:5432/storyteller_test` when running the tests. Do not set it to an application or production database. The helper rejects the same database as `DATABASE_URL` and non-`_test` names. It applies the checked-in Drizzle migrations and truncates domain tables before and after each fixture, so **any data already in this test database will be deleted**. The database user needs permission to migrate and truncate tables. The fixture holds a PostgreSQL advisory lock throughout each test so separate Vitest workers using this helper cannot reset one another's data. It closes the Fastify app and DB pool after the test; media bytes use in-memory storage, never the configured local media directory.

Use `createTestApp(dependencies)` for isolated stubbed route tests; it registers app cleanup automatically. For real HTTP-to-database tests use `const { app, db, storage } = await createBackendTest()` inside a test gated on `TEST_DATABASE_URL`. Invoke `app.inject(...)` rather than starting a listener. Existing `tests/*.test.mjs` tests that opt into `DATABASE_URL` retain their previous behavior and are not affected by this fixture; keep `DATABASE_URL` separate from `TEST_DATABASE_URL` if running both sets together.
